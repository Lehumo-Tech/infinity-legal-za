Executive Summary

Infinity Legal ZA is a production-ready, AI-powered legal practice management platform designed specifically for South African law firms. The system delivers a comprehensive staff intranet with role-based workbench, client-facing portal, and full case management capabilities. All modules are operational, tested, and POPIA-compliant.

The platform serves as a unified digital workspace for attorneys, paralegals, management, and support staff — providing real-time dashboards, document management, lead tracking, consultation scheduling, and firm-wide analytics from a single interface.

Security Features

Infinity Legal ZA implements a comprehensive, multi-layered security architecture designed to meet the requirements of the Protection of Personal Information Act (POPIA) and South African legal industry standards.

🔒
JWT Authentication
24-hour token expiry with automatic refresh. Tokens contain user ID, role, and department claims. Secure HTTP-only cookie storage recommended.
👥
Role-Based Access Control (RBAC)
16 distinct role types with granular navigation, API, and data access control. Each role sees only its authorized portals and data.
🔐
Password Policy
90-day mandatory password expiry with complexity requirements. bcrypt hashing with 12 salt rounds. Dual-hash support for migration.
⏱
Rate Limiting
5 requests per minute for login endpoint. IP-based rate limit tracking with automatic window reset. Prevents brute-force attacks.
🌐
POPIA Compliance
Consent logging for data processing, marketing, third-party sharing, and automated decisions. Full audit trail for data access.
👀
Audit Logging
Every authentication event, document action, and key system operation logged with user ID, IP address, user agent, and timestamp.

🔒 Encryption Standards

All data at rest is protected with 256-bit encryption. Passwords are hashed using bcrypt with 12 salt rounds. JWT tokens are signed with HS256. All API communication occurs over HTTPS. Document locking prevents unauthorized edits on legal files.

Database Schema

The system uses Prisma ORM with SQLite as the database engine. The schema comprises 20 models covering all aspects of legal practice management, from case tracking to compliance logging.

👤 User
Core user model with authentication, role, department, and supervisor hierarchy
Has: Profile, Cases, Tasks, Messages, AuditLogs, Notifications, Consultations
👤 Profile
Extended user profile data with 1:1 relationship to User
Belongs to: User
⚖ Case
Legal matter tracking with type, urgency, status, value, and AI analysis
Belongs to: Client (User), Lead Attorney (User). Has: Documents, Tasks, Messages, Timeline, PrivilegedNotes, Consultations
🎯 Lead
Potential client tracking with source, score, SLA deadlines, and conversion status
Assigned to: Paralegal (User), Officer (User)
📄 Document
Legal document management with workflow status, versioning, locking, and approval chain
Belongs to: Case. Prepared/Approved/Signed by: Users
📝 IntakeSubmission
Client intake form submissions with POPIA consent and AI analysis
Standalone with unique reference ID
📋 Task
Task management with priority, status, due dates, and case linkage
Belongs to: Case (optional). Assigned to/Created by: Users
💬 Message
Case-related messaging system with types: message, note, system, alert
Belongs to: Case. Sender/Recipient: Users
📖 Consultation
Client-attorney meeting scheduling with in-person, video, and phone options
Client (User), Attorney (User), Case (optional)
👀 AuditLog
System-wide audit trail with action, resource, IP address, and user agent
Belongs to: User (optional)
🔔 Notification
User notification system with 8 types and read/unread tracking
Belongs to: User
🔒 ConsentLog
POPIA consent records with type, purpose, granted status, and IP tracking
Belongs to: User (optional)
📅 CaseTimeline
Case activity history with status changes, document filings, and notes
Belongs to: Case
🔒 PrivilegedNote
Attorney-client privileged notes with restricted visibility levels
Belongs to: Case, Author (User)
⚖ Attorney
Attorney professional profile with LPC number, specializations, and availability
Belongs to: User
💰 PricingPlan
Subscription plan definitions with features, limits, and pricing
Has: UserSubscriptions
💳 UserSubscription
User subscription tracking with status, period, and cancellation
Belongs to: User, PricingPlan
📊 ApiAnalytic
API usage analytics with endpoint, status code, and response time tracking
Belongs to: User (optional)
⚠ ErrorLog
Error tracking with type, message, stack trace, and resolution status
Belongs to: User (optional)
💾 BackupRecord
Database backup tracking with type, status, size, and completion time
Standalone
⏱ RateLimitLog
Rate limiting records with IP, endpoint, request count, and window tracking
Standalone (unique on IP+endpoint)
🎯 LeadAssignment
Lead assignment tracking with user and timestamps
Belongs to: User

🗃 Key Relationships

User is the central entity with self-referential supervisor hierarchy. Cases connect to clients, attorneys, paralegals, leads, documents, tasks, and timeline entries. Documents follow a workflow chain: Preparer → Approver → Signer → Supervisor. All actions are audit-logged with IP and user agent for POPIA compliance.

API Endpoints

The system exposes 15 RESTful API endpoints through Next.js API Routes. All endpoints (except auth and health) require JWT Bearer token authentication and enforce role-based access control.

Method Endpoint Description Auth
POST /api/auth/login Staff authentication with JWT token generation and password expiry check Public
POST /api/auth/signup New user registration with role assignment and validation Public
GET /api/dashboard Firm-wide KPIs: case counts, revenue, tasks, leads, client totals JWT
GET /api/cases Paginated case listing with search, type, status, and urgency filters JWT
GET /api/leads Paginated lead listing with source, status, and assignment info JWT
GET /api/consultations Consultation listing with client, attorney, and meeting type details JWT
POST /api/consultations Create new consultation with client, attorney, date, time, and type JWT
GET /api/documents Document listing with workflow status, version, and case association JWT
POST /api/documents/upload Upload document with file, metadata, case ID, and type JWT
GET /api/tasks Task listing with assignee, priority, status, and due dates JWT
POST /api/tasks Create new task with assignment, priority, due date, and case linkage JWT
GET /api/staff Staff directory with supervisor info, department, and activity status JWT
GET /api/notifications User notifications with read/unread status and type filtering JWT
GET /api/analytics Firm analytics: revenue trends, case distribution, performance metrics JWT
GET /api/health System health check endpoint for monitoring and uptime verification Public
GET /api/backup Backup status and database integrity check JWT

🔌 API Conventions

All endpoints return JSON with a { success: boolean, data: {...}, error?: {...} } envelope. Paginated endpoints support ?page=1&perPage=10&search=... query parameters. JWT tokens are sent as Authorization: Bearer <token> headers.
